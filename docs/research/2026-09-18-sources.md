# Research log: project shape and current references

Date: 2026-09-18. The research was performed through the local SearXNG instance and browser research, with primary project documentation opened where possible. Reddit was attempted through the local browser route but was blocked by network security; search snippets were treated as leads, not authoritative evidence.

## What was compared

- [auto-editor](https://github.com/WyattBlue/auto-editor): a mature CLI for audio, motion, preview, and manual-range editing. It validates the value of a scriptable command-line workflow, but its central abstraction is automatic cutting rather than conference speaker boundaries.
- [pyannote-audio](https://github.com/pyannote/pyannote-audio): a widely used local diarization toolkit. It supports the research direction for optional speaker-attribution workflows, but diarization is not identity proof and is intentionally outside this small v0.1 core.
- [PySceneDetect](https://github.com/Breakthrough/PySceneDetect): a popular scene-detection library. It is useful for shot changes, but a camera cut is not necessarily a speaker or Q&A boundary.
- [jumpcutter](https://github.com/carykh/jumpcutter): an influential simple silence-cutting project. It highlights the accessibility of automatic editing, while also showing why a conference tool needs a richer semantic block model.
- [video-chapter-splitter](https://github.com/QiYongchuan/video-chapter-splitter): the closest conceptual analogue: transcript/JSON chapter planning followed by FFmpeg splitting. This project borrows the transparent two-stage shape and adds speaker roles, bilingual names, validation, and a render manifest.
- [dawn-cut](https://github.com/kwakseongjae/dawn-cut), [Prune](https://github.com/SloPOS/Prune), [vidpipe](https://github.com/htekdev/vidpipe), and [cutstorm](https://github.com/vorniches/cutstorm): current local or self-hosted transcript/editor pipelines. They informed the choice to keep the edit plan inspectable, make review a first-class step, and leave room for a future UI without making it a runtime requirement now.

## Decisions

1. **Transcript first, not silence first.** A conference segment is defined by meaning and speaker responsibility. Silence detection can assist discovery but must not be the source of truth.
2. **Human-reviewable JSON.** A plan can be diffed, corrected, regenerated, and audited. A Markdown transcript preserves the source cues used to make the decision.
3. **Stream-copy by default, with verification.** [FFmpeg documentation](https://ffmpeg.org/ffmpeg.html) describes streamcopy as copying packets without decoding or filtering. That makes it the right default for fast, lossless cuts when boundaries are compatible with the source, but keyframe constraints can make arbitrary boundaries inaccurate. The renderer therefore checks the resulting streams and exposes `--accurate` as an explicit re-encode fallback.
4. **Bilingual by design.** English remains the collaboration and repository language; Russian is a supported CLI, documentation, filename, and speaker-name path. A displayed Russian name is stored separately from an original-form name instead of being silently overwritten.
5. **No automatic web identity lookup in the core.** Public-source validation can help resolve an unclear name or title, but it is context-sensitive and privacy-sensitive. The core keeps that investigation outside the render step, where the evidence can be cited and reviewed.

## Real-media validation on 2026-09-18

The plugin was installed through the local Codex marketplace and exercised against a 1920×1080 HLS/MP4 conference recording. A 16-segment stream-copy render preserved H.264/AAC and produced non-empty files, but 15 segments reported `+0.105…+0.125 s` duration drift at non-keyframe boundaries. A 60-second accurate render of the same source produced exact 60.000 seconds with both streams intact and no warnings. This validates the fast default and the need to treat manifest warnings as a required decision point before delivery.

## Limits and follow-up

The first release accepts a timestamped SRT transcript rather than bundling an ASR model. This avoids hidden downloads, large model dependencies, and a false promise that one transcription backend fits every language and recording. A future optional adapter can add local Whisper-family transcription while keeping the JSON plan and FFmpeg renderer unchanged.
