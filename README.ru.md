# Conference Video Cutter

Провайдеро-независимый инструмент для монтажа конференций по транскрипту: превращает одну длинную запись в проверенные выступления спикеров, блоки вопросов и ответов и отдельно помеченные дополнительные фрагменты.

[English version](README.md)

## Зачем он нужен

Запись конференции нельзя надёжно резать только по тишине. В хорошем результате сохраняется полный ответ спикера, вступление и вопросы ведущего отделены от выступления, подготовка и технические паузы остаются проверяемыми, а имена записаны в нужной языковой форме.

Conference Video Cutter делает эти решения явными в небольшом JSON-плане. Он не угадывает границы по одной только тишине и не прячет исходные интервалы в непрозрачном проектном файле.

## Возможности

- двуязычный CLI и документация (`en` / `ru`);
- преобразование транскрипта в читаемый Markdown с исходными таймкодами;
- классификация блоков: открытие, представление, выступление, вопросы и ответы, переход, подготовка, завершение и прочее;
- детерминированные полуинтервалы (`[start, end)`), проверка пересечений и длительности;
- только stream-copy через FFmpeg; программа никогда не перекодирует;
- постпроверка через `ffprobe`, SHA-256 и машинно-читаемый `manifest.json`;
- принимает SRT/VTT/JSON либо явно выбранного облачного провайдера;
- не загружает видео без явного согласия и не требует локального ASR;
- содержит Codex skills и безопасные инструменты preflight, нормализации и проверки экспорта.

Проект разделяет транскрипцию, редакторскую проверку и рендер. Облачный провайдер выбирается явно, локальный ASR остаётся опциональным, а итоговая нарезка воспроизводится по проверенному плану.

## Установка

Сначала установите FFmpeg с [официальной страницы загрузки](https://ffmpeg.org/download.html), затем установите пакет стандартным способом:

```bash
uv tool install git+https://github.com/shubinlab/conference-video-cutter.git
# или из локального checkout:
python -m pip install .
```

Проверьте локальные инструменты:

```bash
cvc doctor
cvc --lang ru doctor
```

Медиа-движок также доступен как отдельный небольшой CLI. Он всегда использует stream-copy через FFmpeg и не поддерживает режим перекодирования:

```bash
cvc-cut probe conference.mp4 --json
cvc-cut cut --input conference.mp4 --start 00:10:00 --end 00:20:00 --output clip.mp4
cvc-cut snap --input conference.mp4 --start 00:10:00 --end 00:20:00 --output clip.mp4 --window 0.25
cvc-cut batch project.json --json
cvc-cut verify output/manifest.json --strict --json
```

`cvc-cut cut` — короткий путь для одного интервала, а `cvc-cut batch` использует тот же проверенный формат проекта, что и `cvc render`. Существующие файлы защищены, пока явно не указан `--force`. При границе не на keyframe CLI покажет предупреждение о дрейфе длительности, а не станет молча перекодировать видео.

`cvc-cut snap` работает строже: он проверяет ближайшие video keyframe-кандидаты, фактическую синхронизацию аудио/видео и длительность. Если безопасной границы нет, команда возвращает `requires-transcode` и не создаёт файл.

## Быстрый старт

1. Получите таймкодированный транскрипт всей записи через импорт SRT/VTT/JSON или явно выбранного облачного провайдера. Сохраните исходный транскрипт как доказательный материал. Локальное распознавание не является обязательным.
2. Создайте каркас проекта:

   ```bash
   cvc --lang ru init --input conference.mp4 --output project.json
   ```

3. Заполните в `project.json` `speakers` и `segments`. Сверьте каждое начало и окончание одновременно с транскриптом и видео. Блок спикера должен начинаться с первого содержательного кадра спикера и заканчиваться после его последнего ответа; представления ведущего и подготовку выносите в `role: extra`, если их нужно сохранить для аудита.
4. Сформируйте читаемый транскрипт:

   ```bash
   cvc --lang ru transcript project.json --output transcript.md
   ```

5. Проверьте план и нарежьте видео:

   ```bash
   cvc validate project.json
   cvc render project.json
   ```

6. Проверьте `output/manifest.json` и воспроизведите клипы. Всегда используется stream-copy; дрейф длительности нужно устранять изменением границы или явно принимать:

   ```bash
   cvc render project.json
   ```

Stream-copy сохраняет исходные закодированные потоки и никогда не запускает видео- или аудиокодек. Он зависит от keyframe, поэтому предупреждения нельзя скрывать — границы нужно менять в edit-плане.

## Файл проекта

Минимальный рабочий план выглядит так:

```json
{
  "language": "ru",
  "source": "conference.mp4",
  "transcript": "transcript.srt",
  "output_dir": "output",
  "copy_streams": true,
  "speakers": {
    "spk-01": {
      "name": "Alexey Example",
      "name_ru": "Алексей Пример",
      "topic": "How to review evidence"
    }
  },
  "segments": [
    {
      "id": "01",
      "speaker_id": "spk-01",
      "title": "Проверка фактов",
      "kind": "main_talk",
      "start": "00:05:00.000",
      "end": "00:25:00.000",
      "role": "speaker",
      "filename": "01 — Проверка фактов — Алексей Пример.mp4"
    }
  ]
}
```

`start` включается, а `end` не включается. Для `role: speaker` нужен существующий `speaker_id`; `role: extra` предназначен для переходов ведущего и технических пауз. Допустимые `kind`: `opening`, `speaker_intro`, `main_talk`, `qa`, `host_transition`, `technical_prep`, `closing`, `other`.

## Результат

Каждый клип записывается в `output_dir`. В манифесте есть исходный интервал, фактическая длительность, отклонение длительности, кодеки, режим, размер файла, SHA-256 и предупреждения по каждому клипу. Верхнеуровневый список `warnings` позволяет поставить дрейф границ на автоматическую проверку:

```text
output/
├── 01 — Проверка фактов — Алексей Пример.mp4
├── 00 — Переход ведущего.mp4
└── manifest.json
```

Исходная запись и реальные транскрипты конференций намеренно не попадают в Git. Для изучения схемы без распространения медиа используйте `examples/demo/`.

## Инструменты Codex

Репозиторий также является Codex-плагином. Его skills описывают cloud-first workflow, проверку спикеров и границ вопросов, а также защиту приватных записей. Встроенные инструменты ничего не загружают:

```bash
python3 scripts/cvc_preflight.py project.json --json
python3 scripts/cvc_normalize_transcript.py transcript.srt --output transcript.cvc.json
python3 scripts/cvc_validate_output.py output/manifest.json --json --strict
```

`cvc_preflight.py` проверяет исходник, транскрипт или провайдера, FFmpeg и место на диске без сетевых запросов. `cvc_normalize_transcript.py` приводит SRT, VTT и распространённый JSON провайдеров к формату `cvc-transcript-v1`. `cvc_validate_output.py` проверяет файлы и хэши и может считать предупреждения рендера ошибкой.

## Границы проекта

Это ядро монтажа и проверки плюс workflow-инструменты Codex, а не база идентификации людей и не непрозрачный облачный редактор. Оно не скачивает записи, не выполняет распознавание лиц, не ищет автоматически имя человека в интернете и не переписывает транскрипт молча. Облачная обработка остаётся явным решением провайдера с согласием пользователя и фиксацией условий обработки.
